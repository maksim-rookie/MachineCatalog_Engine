# Отчёт проверки PDF_SEARCH 8.4.4

## Состояние релиза

- **98/98 тестов** (`python -m unittest discover -s tests -v`).
- Проверены исходные PDF: Lynx 2100/2600, DVF 5000 2nd Gen., DHF 8000/8000ST,
  Mynx II — **4 документа без кэша**.
- Моделей: **25**, всего записей фактов: **1116**.
- Из них **918** записей значений и
  **198** явно неприменимых фактов.
- **610** одиночных числовых значений проходят
  автоматические структурные проверки, но остаются `UNVERIFIED`.
- Замечаний: **66**, проверка полноты
  `True`, проверка качества `False`.
- Кэш: **0/4**, время полного контрольного прогона см. `RUN_TIMING.json`.
- Среда тестирования: Linux, Python 3.13.5, PyMuPDF 1.26.7,
  pdfplumber 0.11.9. Файлы проверены на синтаксис Python 3.11, но
  интеграционный запуск под Windows/Python 3.11 не выполнялся.

## Проверка восьми каталогов старого запуска

Исходные PDF оставшихся четырёх каталогов в окружении отсутствуют.
Проверка сохранённых таблиц `RAW_TABLES.jsonl` из запуска 8.4.3 установила:

- Таблиц: **9**; распознано модельных имён: **42**
  (раньше в реестре было 41, недоставало `DVF 8000T/50`).
- Коллизий заголовков после новой нормализации нет.
- Не сопоставленных с правилом строк в сохранённых основных таблицах: **0**.
- Сохранён один диагностический случай NHP:
  `Table / Tool storage capacity`, единица `kg (lb)`.
- Пропавшая строка NHP `Control / NC system` проверена отдельным геометрическим
  fixture из координат прежнего запуска, без исходного NHP PDF.

**Это геометрический replay, НЕ подтверждение полного нового распознавания
восьми PDF.** Для количественного сравнения 42 моделей требуется поместить
в проект все восемь оригинальных каталогов и повторить `--no-cache`.

## Важные точечные результаты

- `DVF 8000T/50` не сливается с `DVF 8000T` и `DVF 8000/50`.
- Составная масса DVF 5000 разделена на варианты 30, 40, 60 и 120
  инструментов; у 120T некорректная пара массы и фунтов помечена ошибкой.
- В тестах сохранены корректные 330/550 и 290/510 для Lynx и сноски DHF.
- Применимость `N/A` сохранена, а не заменена нулями.
- При некорректной единице и непроверенной восстановленной ячейке числовой
  столбец `MEASUREMENTS_TYPED.csv` остаётся пустым.
