# Строгая проекция machine_spec

Источник ID — справочник пользователя из сообщения чата. Новые field_id не
добавлены и не предлагаются. Конфиг: config/spec_contract/fields.json.
Адаптер отдельный: прежний CATALOG.json и API поиска не изменяются.

Этапы: существующий extract -> mapping по конфигу -> normalize -> applies_to,
тип/единица/домен/физические ограничения -> принятые записи и review -> persist.

Запуск на уже сохранённом прогоне:

python -m catalog_engine.spec_contract --run-dir PATH_TO_RUN --machine-types machine_types.json --output PATH_TO_NEW_OUTPUT

machine_types.json: {"file.pdf":{"MODEL":"vertical_milling"}}.
Тип должен быть указан явно; неизвестный тип не угадывается. Для остальных типов
используются те же функции и applies_to, но реальные примеры пока проверены
только для vertical_milling. Более детальную применимость общих полей необходимо
согласовывать: ограничения явно заданы для токарных, портальных полей и table_count.

Выход: machine_spec.json (только прошедшие отбор), candidates.json (включая
сомнительные значения), NEEDS_REVIEW.json (машина, поле или null для неизвестного
параметра, raw, reason, источник/страница/координаты). Несколько review-событий
могут относиться к одному исходному факту. Нераспознанные параметры не становятся
новыми полями. Существующий извлекатель сохраняет также unmapped_fields.

Соглашения:
- одиночное число для range -> min=max;
- >= / не менее -> min, max=null; <= / до / max -> max, min=null;
- X ± Y -> [X-Y,X+Y]; ±Y -> [-Y,Y]; исходный raw сохраняется;
- интервал для number не сворачивается в скаляр: кандидат с confidence 0.4;
- bool -> value_num 0/1 (в утверждённом списке пока нет bool-полей);
- неизвестная/несовместимая единица -> raw в value_text кандидата, confidence 0.4;
  такой кандидат в принятую таблицу не попадает;
- enum: нормализация пробелов/регистра/HSKA -> HSK-A, проверка разрешённого набора.
  Наборы enum в конфиге — консервативный расширяемый список, не исчерпывающий
  перечень всех стандартов изготовителей;
- точный legacy-ключ/его подтверждённый маппинг и единица: score 1.0;
  предупреждения источника, условия, опции, неоднозначность/аномалии: 0.4.
  Это score правил, не статистически откалиброванная вероятность и не ручное
  подтверждение. Эвристические авто-маппинги не используются;
- конфликтующие варианты одного business key исключаются из принятых записей.

machine_id адаптера — детерминированная идентичность source_file/model/configuration.
Это не PK существующей БД: persist требует явную таблицу соответствия к DB IDs.
Никакого неявного междокументного слияния. persist работает с существующей SQLite
таблицей machine_spec через upsert (machine_id,field_id); таблицы не создаёт.
Нужен существующий UNIQUE и транзакция вызывающего кода. PostgreSQL-драйвер и
автоматическая запись в пользовательскую БД не подключались. Повторный upsert
проверен тестом; файлы проекции детерминированы для одинаковых входов.

Реальные PDF: MYNX — 315 фактов/7 моделей, SVM — 64/2, General — 86 сырых фактов/8
моделей (до разворачивания XYZ). MYNX/SVM: 379 найдено, 291 маппится/обрабатывается,
88 не допущены к маппингу/применимости; итоговые уникальные кандидаты: 32 с score
1.0, 166 с score 0.4; приняты 32. Review: 424 события, не 424 отдельных параметра.
Конфликты единиц воспроизведены на оригинальных PDF: MYNX 28, SVM 2. Подмена единиц
по смыслу заголовка запрещена. Сложные метрические/имперские пары, опции, многозначные
числа и потерянные заголовки требуют дальнейших адаптеров и проверки.

Тесты: python -m unittest discover -s tests -v
Отдельные: python -m unittest discover -s tests -p test_spec_contract.py -v
Новые тяжёлые зависимости не добавлены. Исходные PDF и клиентские результаты
не включаются в исходный дистрибутив. Нагрузка, все шесть типов на реальных PDF,
расширенное покрытие OCR и полнота относительно ручного эталона не подтверждены.
