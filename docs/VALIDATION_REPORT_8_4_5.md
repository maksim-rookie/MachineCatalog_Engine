# Проверка MachineCatalog Engine 8.4.5

Проверка выполнена в Linux, Python 3.12.14, PyMuPDF 1.28.2, pdfplumber 0.11.10. Нативный текст/геометрия PDF, `LOCAL_CELL_OCR=0`, без внешних API, без кэша.

## Тесты

`python -m unittest discover -s tests -v`: **126 тестов, OK**, пропущенных и ожидаемо падающих нет. Включены прежние 98 тестов и 28 новых: полные суффиксы, JSON-словари/инвалидация кэша, горизонтальные и полностью безрамочные таблицы, пустые/неоднозначные ячейки, два класса в одном документе и на одной странице, опции, диапазоны и пересчёт единиц.

Лог: `benchmarks/validation_8_4_5/TEST_RESULTS.txt`.

## Каталог Kaibo

`凯博数控电子样本2025.pdf`: 19 страниц, 13 распознанных таблиц, **38 моделей и 1059 фактов**. Ранее стандартный движок 8.4.4 давал 0 моделей и 0 фактов.

Независимый список `benchmarks/expected_kaibo_845.csv` содержит 190 переписанных из исходного PDF ячеек: ходы X/Y/Z, обороты шпинделя и масса для всех 38 моделей, включая исходные единицы и страницы. Проверено **190 PASS, 0 FAIL**. Команда: `python benchmarks/verify_kaibo_845.py --run-dir output/v8_4_5/run_20261101_192949_557463`. Отчёт: `benchmarks/validation_8_4_5/KAIBO_REFERENCE_CHECKS.json`. Остальные значения полного каталога вручную сплошным образом не проверены.

Они не заполняются рекламными описаниями и не выдаются за подтверждённое штатное оснащение. Поэтому полнота и качество Kaibo остаются непройденными; это диагностированный результат, а не сбой обработки.

## Практические ограничения

Все факты `human_verified=false`. Контрольные сверки не измеряют точность всех данных. Проверены пять PDF; OCR/сканы и матрицы опций с символами не проверены. Словари расширяемы, но не гарантируют поддержку любого нового китайского/русского каталога. Реальный Windows-прогон не выполнялся.

Настройки облачной среды и публикация в ходе этой доработки не изменялись.
