# MachineCatalog Engine 4.8.6

Локальный парсер PDF-каталогов станков: китайские и английские заголовки таблиц, определение класса по таблице/модели, сохранение суффиксов, восстановление столбцов по координатам, JSON-словари, проверка опциональности, диапазонов и единиц.

## Установка и запуск

Windows / Python 3.11+: запустите `INSTALL_DEPS.bat`, создайте рядом с `main.py` папку `pdf`, положите в неё собственные PDF и запустите `START_NO_CACHE.bat`.

Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
mkdir -p pdf
# Поместите свои PDF в папку pdf.
.venv/bin/python main.py --no-cache
```

Папку входных PDF можно задать явно: `python main.py --input /path/to/pdfs --no-cache`. Новые результаты появляются в `output/v4_8_6/`.

Это пакет исходников: он содержит код, JSON-словари, зависимости и команды запуска. Пользовательские PDF, результаты обработки и тестовые каталоги в него не включены.

Для версии 4.8.6 выполнены 34 автоматических теста, включая сквозной тест на синтетическом PDF и повторный запуск через кэш. Реальные пользовательские каталоги и OCR в этой проверке не использовались. Все извлечённые данные остаются `human_verified=false` и требуют ручной проверки. Код возврата 0 означает завершение обработки, а не подтверждение качества. `--strict-quality` возвращает 2 при необходимости проверки. OCR/сканы и произвольные новые таблицы не гарантируются.

## Единая таблица и статусы данных

Широкие CSV (включая `by_series`) строятся через `catalog_engine/presentation.py`.
Габариты объединяются без предположений о порядке длины/ширины/высоты;
быстрые перемещения и рабочая подача остаются независимыми колонками.
Рабочая подача нормализуется в мм/мин, стол и паллета сохраняют свои подписи.
Скалярное значение XYZ распространяется на оси только при явной подписи X/Y/Z
в источнике или в метаданных условия. Противоречия сохраняются как варианты.

Легенда: **- — не указано в каталоге; !- — требуется подтверждение**.
Сам по себе `SOURCE_BLANK` не подтверждает отсутствие: для `-` нужны статусы
`SOURCE_NOT_LISTED` / `ABSENT` либо `SOURCE_BLANK` с
`source_absence_confirmed=true`. `human_verified=false` сохраняет `!-` даже
при успешной автоматической проверке. Ноль является значением.

`TABLE_FIELD_STATUS.csv` хранит отдельные статусы `PRESENT`, `ABSENT`, `REVIEW`
и числовые компоненты; `TRANSFORMATION_AUDIT.json` сохраняет исходные факты
объединённых ячеек с исходными значениями, единицами, условиями и источниками.
В `ALL_MODELS_wide_values.csv` неподтверждённые ячейки пусты; их статусы доступны
в `TABLE_FIELD_STATUS.csv`. Числовые исходные измерения остаются в
`MEASUREMENTS_TYPED.csv`, без строковых маркеров в числовых полях.
`DATA_LEGEND.txt` сопровождает экспорт. Встроенного GUI в этом проекте нет.

Из широких таблиц исключён только явный список `REMOVED` в модуле представления
и ранее настроенные скрытые поля. `rapid_traverse_b_rpm` скрывается, если
заполнено менее 25% зарегистрированных конфигураций текущего запуска.
Общий порог к другим параметрам не применяется. Удаления из исходных фактов,
длинного CSV, сырых таблиц и отчётов документов нет; сохраняйте также оригиналы PDF.
Схема импорта остаётся полной для аудита, целевая таблица — отдельная проекция.

Проверки (Python 3.11+, установленные `requirements.txt`):

```bash
python -m unittest discover -s tests -v
```

Тесты включают генерацию PDF, извлечение, проверку качества, экспорт и повторный
запуск через кэш. Это проверка поддерживаемого формата, а не оценка полноты на
реальных каталогах. Добавляйте обезличенные каталоги для регрессионных проверок
геометрии, OCR и неоднозначных единиц.
