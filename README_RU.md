# Машинные каталоги: форматы, аудит и диагностика

Команды создания окружения, активации и запуска приведены в [Quick Start](README.md).
Python 3.11+. Никакие API-ключи не требуются для локального разбора PDF.

## Входные данные

PDF: сохраняются исходные подписи, единицы, цитаты, координаты, страницы и сырые
ячейки. Правила находятся в `config/schema.json` и `config/dictionaries/`.
Новая неизвестная подпись попадает в `documents[].unmapped_fields`, сохраняя
сырые ячейки. Отсутствие целой группы параметров не останавливает запуск.
Не всякая произвольная таблица распознаётся автоматически: нужны достоверные
границы ячеек либо геометрические привязки моделей, подписей и единиц.

Структурированный JSON — список записей или объект `{"records": [...]}`:

```json
[
  {"model": "MC200", "parameter": "spindle_speed_rpm", "value": 0, "unit": "rpm"},
  {"model": "MC1000", "parameter": "machine_weight_kg", "value": null, "unit": "kg"}
]
```

Также поддерживается объект с `facts` и необязательным `registry`.
Для длинного формата обязательны `model`, `parameter`, `value`; ноль сохраняется.
Для широкого формата обязательна `model`, остальные колонки — параметры:

```csv
model;spindle_speed_rpm;machine_weight_kg;new_custom_parameter
MC200;0;1200;custom value
MC1000;24000;;another value
```

CSV читается как UTF-8 (с BOM или без), с разделителями `,`, `;` или табуляцией.
Excel поддерживает длинный/широкий формат на нескольких листах. Листы без модели
пропускаются с записью причины; другие листы продолжают обрабатываться.
Неизвестные поля сохраняются с предупреждением `unknown_parameter`.
Некорректные строки сохраняются в журнале аудита вместе с исходной записью.
JSON-кэш не является входным каталогом. Итоговый `CATALOG.json` переобрабатывается
командой replay, чтобы не смешать происхождение записей из разных документов.

## Сортировка

Колонки группируются в порядке `category_order` схемы. Стандартный порядок:
Accuracy → Travel → Capacity → Table → Feedrate → Spindle → Sub spindle → ATC
→ Turret → Tailstock → Machine dimensions → прочие группы.
Внутри группы применяется естественная сортировка ключей параметров.
Факты сортируются по категории, параметру, классу/типу, модели, конфигурации,
значению и источнику. Модели: класс → тип → производитель → естественное имя
модели → конфигурация → источник. MC2 идёт перед MC10.
`--sort-by` переносит выбранный параметр на первый уровень сортировки строк.
Неоднозначные диапазоны и составные значения не превращаются в выдуманный скаляр.
Нулевые значения сортируются как числа; пустые значения, `-`, `!-`, null/NaN — в конце.

## Представление и статусы

`CATALOG.json` содержит `format_version`, `columns`, `rows`, `facts`, `measurements`,
`documents`, `quality`, `column_audit`, `summary` и `legend`.
В `rows[].cells` отдельно хранятся `value`, `display`, `status`, `numeric_components`,
`review_reasons`, `human_verification_pending` и `source_fact_ids`.
`measurements[].numeric_value` — число либо null, без строковых маркеров.
Исходные факты и их происхождение доступны по `source_fact_ids`; оригинальные
записи нормализованных импортов сохраняются в `raw_record`.

Легенда: **- — не указано в каталоге; !- — требуется подтверждение**.
Пустая извлечённая ячейка сама по себе не доказывает отсутствие параметра.
Для `-` нужны SOURCE_NOT_LISTED / ABSENT либо SOURCE_BLANK с
`source_absence_confirmed=true`. В структурированном импорте явный маркер `-`
считается декларацией отсутствия; `!-` остаётся неподтверждённым.
Успешное словарное сопоставление не означает ручную проверку и не снимает
предупреждения о конфликтах единиц или источников.

Габариты объединяются без предположений о длине/ширине/высоте. Рабочая подача
нормализуется в мм/мин отдельно от быстрых перемещений. XYZ-скаляр применяется
ко всем осям только при явной подписи XYZ в источнике. Стол и паллета сохраняют
подписи. Повторная проекция и повторная проверка качества идемпотентны.

Из таблицы исключён только явный список REMOVED и ранее заданные скрытые поля.
Ось B скрывается при заполнении менее 25% зарегистрированных конфигураций.
Другие параметры автоматически по порогу не удаляются. Исходные факты остаются
в JSON. Исходные PDF также следует сохранять.

## Старые результаты и проверка

```bash
python -m catalog_engine.replay --run-dir /path/to/old/run --output /path/to/new/replayed --export-csv
python -m unittest discover -s tests -v
```

Replay читает старые отчёты/JSONL или новый CATALOG.json и повторно обрабатывает
сохранённые ячейки и координаты слов. Каталог вывода должен быть новым или пустым.
Это не повторное чтение исходного PDF, не восстановление векторной графики и не OCR.
Оригиналы результатов, входные файлы и кэш не перезаписываются.
Отдельного GUI в проекте нет. Неоднозначные единицы и конфликтующие источники
нельзя исправлять подбором правдоподобных чисел: сохраняются варианты и аудит.
