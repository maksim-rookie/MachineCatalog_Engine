# MachineCatalog Engine v4.8.5.4

Исправлена потеря данных при нормализации и сборке широких таблиц. Полный исходный проект и пересобранные результаты включены в архив.

## С чего начать

1. Для чтения результатов откройте `output/v4_8_5_4_reexport/run_20261102_122644_348279/ALL_MODELS_NORMALIZED_wide.csv`.
2. Для сравнения с оригиналом откройте `ALL_MODELS_NORMALIZED_with_sources.csv`: значение, единица, исходный текст, исходная единица, источник и статус стоят рядом.
3. Для нового разбора положите PDF в `pdf/` и запустите `START_LOCAL.bat` или `python main.py`.
4. Для пересборки сохранённого запуска используйте `python reexport.py --run "PATH_TO_RUN"`. PDF для этой команды не нужны.

## Основные результаты

- `NORMALIZED_PARAMETERS.csv`: исходные и нормализованные записи с происхождением и условиями.
- `ALL_MODELS_NORMALIZED_wide.csv`: полная таблица для чтения; спорные значения видны и помечены.
- `ALL_MODELS_NORMALIZED_with_sources.csv`: сравнение с исходной ячейкой непосредственно рядом.
- `ALL_MODELS_NORMALIZED_values.csv`: строгая таблица без неподтверждённых, условных и опциональных значений; пропуски здесь ожидаемы.
- `NORMALIZED_CELL_STATUS.csv`: причины пустых или неподтверждённых полей.
- `NORMALIZED_PARAMETER_DICTIONARY.csv`: единицы канонических столбцов.
- `NORMALIZATION_AUDIT.csv`, `NORMALIZATION_VARIANTS.csv`: обнаруженные варианты названий, единиц и форматов.
- `NORMALIZATION_SUMMARY.json`: контроль сохранности фактов и заполненности отображения.
- `RUN_DEBUG.log`, `RUN_ABORTED.json`, `EXTRACTION_CHECKPOINT.json`: диагностика и восстановление.

Синонимы подписей — `config/parameter_synonyms.json` и `config/schema.json`; канонические имена, единицы и текстовые формы — `config/normalization.json`; коэффициенты единиц — `catalog_engine/units.py`; разбор новых составных значений — `catalog_engine/canonical.py`. Зоны ответственности модулей описаны в `ARCHITECTURE.md`.

## История и установка


Локальный универсальный парсер технических PDF-каталогов промышленного оборудования. Основные компоненты: восстановление геометрии таблиц, модельная иерархия, нормализация многоязычных параметров, классификация по типу оборудования, сохранение происхождения фактов, проверка полноты, ручные исправления.

## Новое в 4.8.5.4

1. **Иерархия идентичности:** `base_model` → `model_variant` → `configuration` → `condition`/опции. Для DHF обе физические модификации `DHF 8000` и `DHF 8000ST` принадлежат базовой модели `DHF 8000`. Вариант `30000rpm / PSC` — конфигурация, а не новая модель. Для других серий объединение допустимо только при наличии явного правила `model_family_rules` в JSON, а не по совпадающим цифрам.
2. **Новый смысл `ALL_MODELS_wide.csv`:** одна строка на базовую модель. Различающиеся значения снабжаются указанием исходной физической модели и комплектации. Значения без достаточной применимости не подставляются автоматически.
3. **Подробные формы:** `ALL_MODEL_VARIANTS_wide.csv` содержит отдельные физические модификации; `ALL_CONFIGURATIONS_wide.csv` — отдельные комплектации и `model_variant`; `MODEL_FAMILIES.csv` — связь семейства и исходных названий.
4. **Группировка столбцов по техническим разделам:** `Travel → Table → Spindle → Feedrate → Automatic tool changer (ATC) → Machine dimensions → Control`; остальные разделы после основных. Порядок определяется `config/schema.json`, а не сортировкой по алфавиту.
5. **Многоязычные синонимы:** `config/parameter_synonyms.json`, включая DN Solutions и KAIBO CNC. В `ALL_MODELS_long.csv` сохраняются `source_label`, `source_group`, `value_raw`, а также `parameter_normalized`, категория, ID факта, координаты и единицы.
6. **Классификация внутри `machining`:** горизонтальные, вертикальные, пятиосевые, портальные, гравировально-фрезерные, высокоскоростные центры. Для однородных каталогов проверяется явный тип на обложке; для многоотраслевых/многосерийных — заголовок каждой таблицы.
7. **Проверяемые ручные исправления:** `--review-file config/review_overrides.json`. Исправление требует точного `fact_id`, SHA-256 документа, имени проверяющего и причины. Исходная цитата, `value_raw` и координаты остаются неизменными, журнал — `REVIEW_CORRECTIONS_AUDIT.csv`.
8. **Отдельный кэш** `output/cache_v4_8_5_4/` и история `output/v4_8_5_4/run_.../`. Проценты прогресса и время работы сохранены.

## Установка Windows / PyCharm / Python 3.11

Распакуйте архив исходников в новую папку. Откройте её в PyCharm (File → Open), затем терминал (`Alt+F12`).

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Подключите интерпретатор `.venv\Scripts\python.exe` в настройках PyCharm. Поместите PDF в `pdf/` и запустите:

```powershell
.\.venv\Scripts\python.exe main.py --no-cache
```

Вместо команды можно использовать `START_NO_CACHE.bat`. Дополнительно см. [INSTALL_PYCHARM_PY311.md](INSTALL_PYCHARM_PY311.md).

## Изменение правил без правки Python

В `config/schema.json`: `model_family_rules` (явно разрешённые семейства), `cover_machine_types`, `machine_taxonomy`, `parameter_groups` и `parameter_order`. В `config/parameter_synonyms.json`: известные сопоставления названий параметров. Для локальных правил скопируйте `config/overrides.example.json` в `config/overrides.json`, не редактируя базовый файл. Новые точные aliases можно добавить через поле `parameter_synonyms`.

**Пример DHF:** `DHF 8000ST` остаётся физической моделью с вариантом `ST`; его паллета Ø1000 не переносится на стандартное исполнение, а магазин 80 инструментов относится только к `30000rpm / PSC`.

**Ручная проверка:** откройте `ALL_MODELS_long.csv`, выберите `fact_id` и `source_sha256` из `RUN_MANIFEST.json`, заполните поля `config/review_overrides.json` по `config/review_overrides.example.json`. Для повторного запуска используйте `--review-file` и `--no-cache`. Ручная поправка не редактирует исходный PDF и `value_raw`.

## Ограничения

`exit code 0` означает успешное выполнение программы, а не абсолютную достоверность значений. Распознавание отдельных таблиц без текстового слоя, сложных матриц опций и неоднозначных единиц требует проверки. Результаты v4.8.5.1 остаются отдельно; новый экспорт использует другую гранулярность базовой модели и не должен перезаписывать старые файлы.
