# MachineCatalog Engine 8.4.5.1

Локальный парсер PDF-каталогов станков. В этой версии исправлены причины видимых пропусков в `ALL_MODELS_wide.csv`: раздельные категории одинаковых параметров, отсутствие осевых компонентов, неверные единицы в широкой таблице и исключение небазовых конфигураций из представления моделей.

## Папки проекта и данных

```text
родительская_папка/
├── MachineCatalog_Engine_8.4.5.1/      # проект
│   ├── main.py
│   ├── catalog_engine/
│   ├── config/                       # схема и многоязычные словари
│   ├── tests/                        # тесты; контрольные PDF — снаружи
│   ├── benchmarks/                   # эталонные CSV и средства проверки
│   ├── tools/reexport_run.py         # повторный экспорт сохранённого запуска
│   └── docs/
└── MachineCatalog_Engine_data/       # рабочие данные вне проекта
    ├── input/                        # ваши PDF
    ├── runs/v8_4_5_1/                # отдельная папка на каждый запуск
    ├── cache/v8_4_5_1/
    └── history/                      # сохранённые прежние данные в облачной среде
```

В проекте больше нет папок `pdf` и `output`. По умолчанию данные находятся рядом с проектом. `--data-dir <путь>` или переменная `MACHINECATALOG_DATA_DIR` задают другой внешний корень. `--input`, `--output`, `--cache` позволяют отдельно выбрать каталоги. Создавать корень данных внутри проекта через `--data-dir` запрещено.

## Windows / Python 3.11+

1. Распакуйте исходники в отдельную папку и запустите `INSTALL_DEPS.bat`.
2. В терминале проекта выполните:

   ```powershell
   .\.venv\Scripts\python.exe main.py --init-data
   ```

3. Программа напечатает расположение `input`, результатов и кэша. Положите PDF в `input`.
4. Запустите `START_NO_CACHE.bat` или:

   ```powershell
   .\.venv\Scripts\python.exe main.py --no-cache
   ```

Для PyCharm выберите `.venv` и корень проекта в качестве рабочей папки. В параметрах Run можно указать `--input "D:\Catalogues" --no-cache` или `--data-dir "D:\MachineCatalogData" --no-cache`.

## Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py --init-data
# Добавьте PDF во внешний input.
LOCAL_CELL_OCR=0 .venv/bin/python main.py --no-cache
```

В текущей облачной среде рабочая папка проекта сохранена: `/workspace/PDF_SEARCH_v8_4_4_LOCAL`. Используйте интерпретатор `/workspace/venvs/pdf-search/bin/python`; данные перенесены в `/workspace/MachineCatalog_Engine_data`. Старые PDF и результаты сохранены с проверкой контрольных сумм, а не удалены.

## Результаты

`LATEST_RUN.txt` во внешней папке `runs/v8_4_5_1` указывает на последний запуск.

- `ALL_MODELS_wide.csv` — одна строка на модель, единая категория для каждого параметра, все конфигурации с явными пометками. По умолчанию параметры не скрываются.
- `ALL_CONFIGURATIONS_wide.csv` — отдельные строки конфигураций.
- `ALL_MODELS_long.csv` — исходные факты и разобранные компоненты с `parent_fact_id`, `derivation`, `value_raw`, единицами, страницей и координатами.
- `WIDE_EXPORT_AUDIT.csv/json` — для каждого факта указан целевой столбец и отображённое значение; проверяется фактическое присутствие этого значения в широкой таблице. Покрытие экспорта не равно полноте распознавания PDF.
- `ALL_MODELS_wide_values.csv` — просмотр значений без блокирующих предупреждений и исключительно опциональных записей; файл не является полностью числовой таблицей.
- `MEASUREMENTS_TYPED.csv` — отдельный числовой слой с проверкой единиц, коэффициентом пересчёта, границами диапазонов и статусами.
- `ALL_MODELS_options.csv` — опциональное оснащение. Оно не считается штатным и не заполняет обязательные штатные поля.
- `RAW_TABLES.jsonl`, `SOURCE_PAGES.jsonl` — геометрия таблиц, текст и слова со всех страниц, в том числе не преобразованные в характеристики.
- `MODEL_REGISTRY.json`, `MODEL_QUALITY.csv`, `UNMAPPED_FIELDS.csv`, `NEEDS_REVIEW.json`, `RUN_SUMMARY.json` — идентификация, полнота, непривязанные строки, замечания и итог.

Пример: исходная масса `35 t` сохраняется в long; в столбце `_kg` широкого CSV показывается `35000 [исходник: 35 t]`, а в числовом слое — `35000 kg`. Ячейка `20/20/20` при явном заголовке X/Y/Z остаётся исходным фактом и дополнительно получает три компонента с привязкой к исходной ячейке. Порядок габаритов не угадывается по одной надписи `外形尺寸`.

## Повторный экспорт присланного запуска

Распакуйте архив запуска, затем:

```bash
python tools/reexport_run.py --run /path/to/run_20261101_225902_841960 --output /external/results/fixed_run
```

Целевая папка должна быть новой и находиться вне проекта. Скрипт читает сохранённые факты и координаты; он **не распознаёт PDF повторно**. В результатах это отмечено `processing_mode=saved_run_reexport`, `pdf_reextracted=false`. Оригинальный запуск не перезаписывается.

## Проверки и ограничения

```bash
LOCAL_CELL_OCR=0 .venv/bin/python -m unittest discover -s tests -v
python benchmarks/verify_v843.py --run-dir /external/run
python benchmarks/verify_kaibo_845.py --run-dir /external/run
```

Тесты реальных каталогов ищут контрольные PDF во внешнем `input` и явно пропускаются, если они отсутствуют. В архив исходников PDF не включены. В проверенной облачной среде контрольные файлы сохранены и эти проверки выполнялись.

Все факты имеют `human_verified=false`. Код возврата `0` — обработка завершена, `1` — ошибка, `2` при `--strict-quality` — результат сохранён, но требует проверки качества. В Kaibo система ЧПУ отсутствует в таблицах, а магазины инструментов указаны как опция либо отсутствуют: эти поля не выдумываются. Рекламный текст, рисунки и схемы не становятся автоматически подтверждёнными характеристиками. Сканы/OCR, матрицы опций с символами и произвольные новые структуры требуют отдельной проверки. Windows-команды сохранены; реальный прогон выполнен в Linux.
